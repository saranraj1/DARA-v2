## Review Checklist

Evaluate each area. Be strict. When in doubt, reject.

1. CORRECTNESS: Does the patch actually fix the root cause? Not just the symptom?
2. COMPLETENESS: Are there other code paths that need the same fix?
3. REGRESSIONS: Could this change break any existing functionality?
4. SECURITY: Does the patch introduce injection, auth bypass, or data exposure risks?
5. NULL SAFETY: Are all new code paths null-safe?
6. ERROR HANDLING: Does the patch handle error cases properly?
7. CODE STYLE: Does it match the existing codebase style?
8. MINIMAL: Is the patch minimal, or does it make unnecessary changes?
